# Changelog

All notable changes to QUMO are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

QUMO is a research prototype. Its version string is `0.1.0` (`build/qumo version`) and has not changed since the first commit, and there is no tagged release yet. Until there is one, entries are grouped under "Unreleased" by pull request and date, newest first. Entries are taken from the titles and descriptions of the merged pull requests and from the commit history before pull requests were used; nothing here was added from memory.

## [Unreleased]

### Fixed

- MCP server: `max_iterations` has a ceiling of 1000000 per call (`qumo_run_qasm`, `qumo_run_device`), refused with QM-E913 like `shots` and `max_qubits`. Before, `{"qasm": "... while (true) { x q[0]; } ...", "max_iterations": 9000000000000000000}` blocked the single-threaded server, `ping` included. The CLI keeps its range. (project review, 2026-11-25)

### Changed

- **Behaviour change**: `evolve`, `expectation`, `GpuStateVector.evolve` (so `evolve_gpu`/`expectation_gpu`) and `run_estimator` now raise `QM-E416` for a circuit with a `reset`, a noise channel or a mid-circuit measurement. They used to drop those instructions silently and return the noiseless value (`x; reset` gave `<Z> = -1`, true `+1`; `expectation(x_error(1.0))` gave `+1`, true `-1`). Terminal measurements, barriers and annotations are still ignored. To drop the noise on purpose, use the new `Circuit.without_noise()` (Python: `qumo.expectation(..., noise="ignore")` does it); otherwise use `sample` or the density-matrix simulator (`check_pure_state_circuit` in `qumo/sim/runner.mojo`; `docs/SIMULATION.md`, `docs/ERRORS.md`).

### Fixed


- Integer keys that overflowed at wide registers. `subspace_ground_state` packed `(state << 21) | index`, which wraps once a basis state has a bit at position 43 or higher, so at 44 to 48 qubits the lookup found nothing (H projected to 0, energy 0.0) or raised a false "listed twice" QM-E802; it now sorts the caller indices by state and compares whole states. `lie_closure` de-duplicated on `x * 4294967311 + z`, which is not injective past 32 qubits, so distinct Pauli strings were dropped (`{X1, Z33 Z4 Z3 Z2 Z1}` gave 1 instead of 3); it now keeps a hash index that compares the full (x, z) masks, valid to 64 qubits. Tests in `tests/test_sqd.mojo` and `tests/test_algorithms_tier1.mojo`.
- OpenQASM: a `gate` definition with the name and signature of a native gate was dropped and the native gate ran, whatever the body said (`gate h a { x a; } h q[0];` gave an H). The body is now compared with the native unitary (up to global phase, up to 4 qubits): an equal definition still maps to the native opcode, so `to_qasm` output round-trips as before, and a different one (or one that cannot be compared) is used as written with the new warning QM-W056. Every definition `to_qasm` and `to_qasm2` write was checked and matches its native gate.
- Pauli text inputs are checked (`qumo/ir/pauli.mojo`): `PauliSum.add_label` and `PauliTerm.label(n)` raise QM-E302 past 64 qubits (a 65-character label used to wrap and put the Pauli on the wrong qubit, silently); `parse_pauli_sum` raises QM-E301 for a qubit repeated inside one term (`"X0 Z0"` used to give `Y0`, `"Z0 Z0"` gave `Z0`) and for a sign with no term after it (`"Z0 +"` used to add a spurious identity term). `PauliTerm.label` now `raises`. Inputs that were correct give the same result.
- OpenQASM slices: negative bounds are normalised before the range is walked, so `q[0:-1]` is the whole register and `q[-3:-1]` the last three qubits (it used to select nothing); a range that selects no qubits, bits or elements (`q[2:1]`) is now error `QM-E521` with line and column instead of aborting the process ("index 0 is out of bounds") or reading the next operand's qubit. Out-of-range slice bounds are reported even when the range is empty.
- The resource estimator counted three synthesised rotations for every constant `U` gate, so `U(pi/2, 0, pi)` (H) and `U(0, 0, pi/4)` (T) were reported as non-Clifford rotations. Constant angles are now classified as for `RZ`/`RY`: a multiple of pi/2 is free, an odd multiple of pi/4 is one T, and when theta is a multiple of pi the two Rz merge into one rotation by phi + lambda (phi - lambda for an odd multiple). Symbolic angles still count three. `recommended_method` and `is_clifford()` are unchanged (they still treat `U` as non-Clifford). (`qumo/exec/resources.mojo`, `tests/test_orchestrator.mojo`)om/ANFAIA/QUMO/pull/1), 2026-11-03)

### Fixed

- `MatchingGraph`, `graphlike_dem` and the correlated decoder indexed `comp_dets[c][0]` for every `^` piece, so a DEM piece with no detector (`error(0.1) D0 ^ L0`, legal Stim) aborted the process with an out-of-bounds assert, and a piece with more than two detectors lost the extra ones. One helper, `graph_pieces` (`qumo/qec/decoders.mojo`), now decides: an observable-only piece is folded into the adjacent piece (its observable mask XORed in), a mechanism with no detector is skipped as undetectable, and a piece with more than two detectors is decomposed against the existing edges like an undecomposed hyperedge (dropped and counted if it cannot be). Tests in `tests/test_stim_interop.mojo`.
- MCP and CLI tool calls refuse an argument name their input schema does not declare, with QM-E801 that names it and lists the allowed names, before the tool runs. Before, a misspelt key (`shot` for `shots`) was silently ignored and the default was used, which gave a wrong answer without an error. Found by an audit of every shipped tool: `qumo_statevector`, `qumo_expectation`, `qumo_estimate_resources`, `qumo_emulate`, `qumo_density`, `qumo_to_pbc` and `qumo_ft_encode` read a `program` argument that their schemas did not list; the schemas now declare it.
- Pauli-frame sampler: a `CORRELATED_ERROR(0)` drew its geometric skip from `log1p(-0) = -0`, so the quotient was +-inf and `Int()` of it is platform-defined (a negative position would have written outside the batch). p = 0 now never draws, and the op still resets the chain, so a following `ELSE_CORRELATED_ERROR` is unchanged. Same-class check of the other channels: they were already guarded (`if p > 0`); the detector error model already ignores p <= 0. Found by reading after the Stim fix for `broadcast_pauli_errors` (Stim PR #1131); on macOS ARM64 the old sampler gave the right counts, so this is a latent undefined-behaviour fix, not a visible wrong result.

### Changed

- CLI options are strict: an option a command does not declare is a usage error (QM-E921, exit code 2) with a "did you mean" hint. Unknown options were ignored before, so a misspelt `--shot 10` ran with the default. `--quiet`, which was accepted and did nothing, is gone. `qumo help <unknown command>` exits with code 2 (QM-E912). The CLI moved to `cli/app.mojo` (`run_cli`, testable in process); `cli/main.mojo` is the entry file. (project review, 2026-11-10; not yet merged, as the next two entries)
- `sample_auto` / `sample_on` (Mojo) and `qumo_py.sample_device` raise QM-E402 for a circuit without measurements whichever simulator is picked. A Clifford circuit routed to the tableau or Pauli-frame sampler returned `{"": shots}` before. The CLI and the MCP tools are unchanged: they measure all qubits and add the note QM-W004.
- `qumo_py` argument checks, all of which returned a wrong or empty result before: `Circuit.depth_of` raises QM-E913 for an unknown gate name and QM-E911 for a wrong type (it returned 0); a `str` basis in `transpile` is one spec, a basis-set name such as `"sc_cz"` or a comma list, not a sequence of characters; `sample` and `sample_device` refuse `shots` and `seed` that are not integers (QM-E911) and do not convert them; `decode_dem` checks its arguments; `inject_noise` raises QM-E913 for input it cannot address and no longer returns the text unchanged, and it handles one-line OpenQASM and `measure q -> c`.
- Examples are organised by category instead of by SDK, and every example header names its origin (`Framework:` line). ([#4](https://github.com/ANFAIA/QUMO/pull/4), 2026-11-05)
- The README was shortened from 240 to 65 lines; what it dropped moved to `docs/GETTING_STARTED.md`. ([#5](https://github.com/ANFAIA/QUMO/pull/5), 2026-11-09)
- Migrated to Mojo 1.2 and MAX 26.7; `make setup` updates an existing `.venv`. (commits 6a856cf and 11e15b5, 2026-11-01)

### Security

- OpenQASM source is capped in what it can expand to (gate calls, unrolled loops, broadcasts, `pow`): a few bytes of source could previously ask for any amount of memory, including through the MCP server. ([#1](https://github.com/ANFAIA/QUMO/pull/1), 2026-11-03)
- MCP server: one message is at most 1 MiB (a longer line is dropped and answered with a parse error), and a call is refused with QM-E913 above `shots` = 1,000,000 or `max_qubits` = 30. The CLI and the Mojo and Python APIs keep the tools' own ranges. (security pass, 2026-11-13; not yet merged, as the next entry)
- Agent layer: the research tools fetch only public `https` addresses on the default port, the API tools only `export.arxiv.org`, `pypi.org` and `api.github.com`, every redirect is checked again and loses the `Authorization` header. `run_check` passes no variable whose name looks like a credential, takes no absolute path, and limits `git diff` / `git status` to `--stat`, `--name-only`, `--name-status`, `--cached`, `--staged`. The `autoresearch` agent no longer has the web tools; it asks `research-watch`. Commands still run without an operating-system sandbox.
