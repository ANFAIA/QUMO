# Changelog

All notable changes to QUMO are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

QUMO is a research prototype. Its version string is `0.2.0` (`build/qumo version`), set on 2026-11-25 after the fixes and reorganisation of pull requests #41 to #60; it was `0.1.0` from the first commit until then. There is no tagged release yet. Until there is one, entries are grouped under "Unreleased" by pull request and date, newest first. Entries are taken from the titles and descriptions of the merged pull requests and from the commit history before pull requests were used; nothing here was added from memory.

## [Unreleased]

### Changed

- Agents: the security rules of the two harnesses (Python `agents/qumo_agents`, Mojo `agents/mojo`) are specified once, in `agents/spec/guard_rules.json`: the lists both need (skip directories, secret-looking names, the `run_check` allow-list and argument characters, git flags, `build/qumo` subcommands and options, API hosts, redirect limit, environment-name patterns, the web and exec tool groups) and 287 test vectors (an input, and allowed or refused with a reason class) for paths, commands, URLs and redirect chains, environment names, model-key URLs, delegation graphs and the untrusted-data wrapper. Python loads the lists at import (`qumo_agents/guard_spec.py`); Mojo reads them through `core/guard_rules.mojo`, generated by `agents/spec/gen_mojo_rules.py` (a stale copy fails both test suites). `agents/tests/test_guard_spec.py` and `agents/mojo/tests/test_guard_spec.mojo` run every vector through the real functions of each harness. Both harnesses stay. `agents/spec/README.md` lists the differences that remain and why (Mojo confines `run_check` with the OS sandbox and passes an allow-list environment; Python does neither).
- Agents, differences the vectors exposed, each closed towards the stricter side:
  - Python `run_check`: arguments are ASCII and matched whole (`\w` accepted any Unicode letter, `$` a trailing newline).
  - Python path rules: skip directories are compared case-folded, so `.GIT/config` or `Build/x` no longer reach the excluded trees on a case-insensitive file system. Both harnesses also fold U+017F and U+212A (`model\u017f/` opened `models/` on APFS).
  - Python `openrouter` and `local` back ends, and the alphaXiv MCP client: a key is sent over plain `http` only to this machine (`localhost`, `*.localhost`, `127.0.0.0/8`, `::1`), as in the Mojo harness. A local server keeps working; a keyless server on the local network too. **A server on another host that needs `QUMO_AGENTS_LOCAL_API_KEY` must now be reached over `https`.**
  - Mojo `is_secret_env_name`: a name holding `TOKEN`, `SECRET`, `KEY`, `PASSWORD`, `CREDENTIAL` or `COOKIE` (was `*_API_KEY`, `*_TOKEN`, `*SECRET*`, `*PASSWORD*`), so `redact_all` also hides the values of `X_APIKEY`, `SSH_KEY` or `GOOGLE_APPLICATION_CREDENTIALS`.
  - Both: a research fetch refuses IPv4-compatible (`::a.b.c.d`) and multicast addresses and judges a NAT64 address (`64:ff9b::/96`) by the IPv4 address it embeds; `ipaddress.is_global` and its Mojo port call all three global.
  - Mojo: the web+exec delegation check (`check_web_exec`, at registry load) and the untrusted-data wrapper around the answer of each subagent listed in `untrusted_subagents`; both existed only in Python.
- Version string `0.2.0` (was `0.1.0`): `build/qumo version`, the MCP server info, `qumo.__version__`, `pyproject.toml` and `CITATION.cff`. The hardware plugin and the agents package keep their own versions.

### Fixed

- Two changes had taken the error code `QM-E738` (the 3-qubit-gate refusal of `apply_noise_model` and the scope errors of `qumo.ft.faults`), which made the error catalogue fail its uniqueness check. `apply_noise_model` now raises `QM-E739`; `qumo.ft.faults` keeps `QM-E738`.
- Agents (Python harness): `run_check` and the Claude Code / Codex back ends dropped `GIT_CONFIG_KEY_n` from the child environment (the name matches the secret pattern) and kept `GIT_CONFIG_COUNT`, so every `git` command exited 128 with "missing config key GIT_CONFIG_KEY_0" when the parent passed git configuration through the environment. The group (`GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_n`, `GIT_CONFIG_VALUE_n`, `GIT_CONFIG_PARAMETERS`) is now dropped whole; its values can hold credentials (`http.extraheader`).
- The Python extension registers `Circuit`, `Program` and `QecMemory` with their module (`qumo_py`), so importing it no longer gives "builtin type Circuit has no __module__ attribute" (a warning, and an abort under `python -W error`).
- CI: the nightly job also runs `make test-py` (Python package, examples runner, heterogeneous examples, hardware plugins) and `make test-agents`; pull requests get a Python static check (ruff, error rules only).
- Native agent harness (`build/qumo-agent`), macOS: a confined `run_check` and the confined build of a generated tool no longer read the home directory, except what they need. The `sandbox-exec` profile denied a list of names (`.ssh`, `.aws`, the other top-level dot entries, some `Library` directories), so a program run from a sandbox could `cat ~/code/other/.env`, `~/Documents/notes.txt` or the main checkout's `agents/agents.local.json`, and its output went back to the model. Now `$HOME` is denied as a whole and the caller names what is readable: the sandbox, the main checkout's `.git` and `build` and the two virtualenvs with their interpreters for `run_check`; `qumo/`, `agents/mojo/` and the toolchain for a build (`Confinement.list_dirs`, `home_read_rules`, `venv_read_paths` in `agents/mojo/qumo_agent/native/sandbox.mojo`; `agents/mojo/DESIGN.md` 2.1.8 and 6.8). The Linux (Landlock) rules were changed the same way, from read access on `/` to everything outside `$HOME` plus the named paths; they are compile-checked, not run. The Python harness does not confine `run_check` at all (`docs/AGENTS.md` section 7). (project review, 2026-11-25)
- MCP server: `max_iterations` has a ceiling of 1000000 per call (`qumo_run_qasm`, `qumo_run_device`), refused with QM-E913 like `shots` and `max_qubits`. Before, `{"qasm": "... while (true) { x q[0]; } ...", "max_iterations": 9000000000000000000}` blocked the single-threaded server, `ping` included. The CLI keeps its range. (project review, 2026-11-25) ([#55](https://github.com/ANFAIA/QUMO/pull/55), 2026-11-25)
- Integer keys that overflowed at wide registers. `subspace_ground_state` packed `(state << 21) | index`, which wraps once a basis state has a bit at position 43 or higher, so at 44 to 48 qubits the lookup found nothing (H projected to 0, energy 0.0) or raised a false "listed twice" QM-E802; it now sorts the caller indices by state and compares whole states. `lie_closure` de-duplicated on `x * 4294967311 + z`, which is not injective past 32 qubits, so distinct Pauli strings were dropped (`{X1, Z33 Z4 Z3 Z2 Z1}` gave 1 instead of 3); it now keeps a hash index that compares the full (x, z) masks, valid to 64 qubits. Tests in `tests/test_sqd.mojo` and `tests/test_algorithms_tier1.mojo`. ([#51](https://github.com/ANFAIA/QUMO/pull/51), 2026-11-25)
- `circuit_from_json` checks the values an instruction carries, not only the sizes (QM-E911): a negative `clbit` on a measure (it loaded and returned counts `{"": 1024}`), an observable `index` outside 0 to 63 (the simulators hold observables in a 64-bit mask; `99999999999` made `num_observables` 1e11 and hung), a record that does not exist yet (negative counts back from the latest measurement, as in the pragma), a condition bit below 0 (it meant "no condition") or a value other than 0 or 1, a qubit outside the register, a probability outside [0, 1] or a channel that adds past 1, a Pauli letter outside 1 to 3, and a Kraus matrix of the wrong size. Documents the writer produces still load. `tests/test_circuit_json_bounds.mojo`. (project review, 2026-11-25) ([#56](https://github.com/ANFAIA/QUMO/pull/56), 2026-11-25)
- OpenQASM: a `gate` definition with the name and signature of a native gate was dropped and the native gate ran, whatever the body said (`gate h a { x a; } h q[0];` gave an H). The body is now compared with the native unitary (up to global phase, up to 4 qubits): an equal definition still maps to the native opcode, so `to_qasm` output round-trips as before, and a different one (or one that cannot be compared) is used as written with the new warning QM-W056. Every definition `to_qasm` and `to_qasm2` write was checked and matches its native gate. ([#46](https://github.com/ANFAIA/QUMO/pull/46), 2026-11-25)
- Pauli text inputs are checked (`qumo/ir/pauli.mojo`): `PauliSum.add_label` and `PauliTerm.label(n)` raise QM-E302 past 64 qubits (a 65-character label used to wrap and put the Pauli on the wrong qubit, silently); `parse_pauli_sum` raises QM-E301 for a qubit repeated inside one term (`"X0 Z0"` used to give `Y0`, `"Z0 Z0"` gave `Z0`) and for a sign with no term after it (`"Z0 +"` used to add a spurious identity term). `PauliTerm.label` now `raises`. Inputs that were correct give the same result. ([#44](https://github.com/ANFAIA/QUMO/pull/44), 2026-11-25)
- OpenQASM slices: negative bounds are normalised before the range is walked, so `q[0:-1]` is the whole register and `q[-3:-1]` the last three qubits (it used to select nothing); a range that selects no qubits, bits or elements (`q[2:1]`) is now error `QM-E521` with line and column instead of aborting the process ("index 0 is out of bounds") or reading the next operand's qubit. Out-of-range slice bounds are reported even when the range is empty. ([#42](https://github.com/ANFAIA/QUMO/pull/42), 2026-11-25)
- `qumo_vqe` and `qumo_qaoa_maxcut` no longer abort the MCP server on a wide request (`num_qubits: 46`, graph `0-45`): both check the width against a new `max_qubits` argument (default 24) and answer QM-E930, and QAOA checks the 26-node limit (QM-E807) before the optimisation instead of after. `ExpectationEngine`, `PauliOperator`, `run_estimator` and `qaoa_maxcut` raise the existing QM-E404 / QM-E807 for a direct caller instead of allocating 2^n. ([#57](https://github.com/ANFAIA/QUMO/pull/57), 2026-11-25)
- Shot-based `run_estimator` (`precision > 0`): the standard error summed the per-term variances although the terms of a qubit-wise-commuting group come from the same shots, so `Z0 - Z1` on a Bell pair reported 0.014 (true 0) and `Z0 + Z1` 0.014 (true 0.02). It now takes the variance of the per-shot weighted sum, with one helper (`qwc_setting`, `qwc_group_stats` in `qumo/exec/primitives.mojo`) shared with `sampled_expectation` / `noisy_expectation`. `precision` is now the standard error it promises: shots per setting = ceil(sum over groups of (sum |coeff|)^2 / precision^2) (before `1/precision^2 + 1`, so `10*Z` at 0.01 gave 0.1); shot counts grow with the coefficients, up to 10,000,000 (QM-E913 past it, or for a non-finite precision). An observable on a qubit the circuit lacks raises QM-E405 (shot mode returned 1.0 for `Z5` on one qubit). Shots now come from the real sampler, so reset, noise, mid-circuit measurement and classical control count (`x; reset` gave -1, now +1). The state is re-sampled per group instead of evolved once, so a many-group Hamiltonian is slower. `examples/chemistry_and_physics/ucc_vqe.mojo` sets its precision from this rule. ([#53](https://github.com/ANFAIA/QUMO/pull/53), 2026-11-25)
- The resource estimator counted three synthesised rotations for every constant `U` gate, so `U(pi/2, 0, pi)` (H) and `U(0, 0, pi/4)` (T) were reported as non-Clifford rotations. Constant angles are now classified as for `RZ`/`RY`: a multiple of pi/2 is free, an odd multiple of pi/4 is one T, and when theta is a multiple of pi the two Rz merge into one rotation by phi + lambda (phi - lambda for an odd multiple). Symbolic angles still count three. `recommended_method` and `is_clifford()` are unchanged (they still treat `U` as non-Clifford). (`qumo/exec/resources.mojo`, `tests/test_orchestrator.mojo`)
- Agent tools `list_files` and `search_code` (`agents/qumo_agents/tools/repo.py`) no longer list or return lines of secret-looking files (`.env`, `secrets.yaml`, `*.pem`, `*.key`, anything under a secret-named directory) or of symlinks that leave the repository; `read_file`, `write_file`, `edit_file`, `list_files` and `search_code` now share one path rule (`_forbidden`), as the Mojo port already did. ([#41](https://github.com/ANFAIA/QUMO/pull/41), 2026-11-25)
- `sample_ptsbe` mis-simulated PAULI_CHANNEL_2 (it read the table offset as a probability, so `t(0); pauli_channel_2` with XX certain gave `{"00": 200}` where `sample` gives `{"11": 200}`) and CORRELATED_ERROR / ELSE_CORRELATED_ERROR (it read the Pauli-table offset as a qubit, a possible out-of-range write). PAULI_CHANNEL_2 now uses its table and matches `sample`; E and ELSE are refused with QM-E414, as is any noise instruction the sampler does not know. This also reaches `emulate`. Tests in `tests/test_noise_sim.mojo`. ([#45](https://github.com/ANFAIA/QUMO/pull/45), 2026-11-25)
- `remove_identities`, the first pass of every preset, dropped each rotation below about 2e-6 rad on its own, so many small rotations that add up were all deleted: `h q0; 300000 x rz(1.9e-6) q0; h q0` (= `rz(0.57)`, P(1) = 0.079) compiled to an empty circuit at O1, O2 and O3. It now drops a gate only when it equals the identity to 1e-14, in flat `transpile` and in Program blocks alike. Rotations between 1e-14 and 2e-6 (`rx(1e-9)`) are no longer removed on their own. Regression test `test_small_rotations_accumulate` in `tests/test_compiler.mojo`. (deep pass of 2026-11-25) ([#47](https://github.com/ANFAIA/QUMO/pull/47), 2026-11-25)
- A classically conditioned `LogicalProgram.pauli_exp` (`c_if` / `c_if_register`) was applied unconditionally by the Iceberg implementation, and `logical_to_circuit` skipped the condition too, so the reference hid the bug (Iceberg k=4, `pauli_exp(pi, "XXXX")` then `c_if(0, 1)` with c0 = 0 gave 11110 instead of 00000). Both now honour the condition, like the conditioned rz/rzz. `LogicalProgram.validate` also checks the handles of `pauli_exp` are live (QM-E727; before, `Engine.pauli_exp` indexed unchecked) and rejects an all-identity string or a repeated handle (QM-E724; the reference path read past an empty ladder). (`qumo/ft/implement.mojo`, `qumo/ft/emulate.mojo`, `qumo/ft/logical.mojo`, `tests/test_ft_encode.mojo`) ([#49](https://github.com/ANFAIA/QUMO/pull/49), 2026-11-25)
- `qumo.ft.encode.compile`: a measured qubit that is used again, and a classical-lane qubit that read a clbit, now use the value from when it was measured / read even if the clbit is overwritten in between (before, the logical program used the new value: `x(0); measure(0,0); h(1); h(1); measure(1,0); z(0); measure(0,1)` compiled to c1=0, the source gives 1). `compile` copies the bit to a fresh private clbit only when such an overwrite happens, so every other compiled program is unchanged; the copies show up as extra leading clbits, and a copy past the 62-bit register raises QM-E406. Test: `test_clbit_reuse_after_overwrite` in `tests/test_ft_encode.mojo`. (project review, 2026-11-25) ([#52](https://github.com/ANFAIA/QUMO/pull/52), 2026-11-25)
- `post_layout(call_limit=N)` runs. The argument check accepted it and its own hint printed it, but the pass stripped only `window=` and failed with "String is not convertible to integer" (`post_layout(N)` worked). `compile_spec_program` refuses the learned router for `policy = auto` too: it looked for the text `policy=` and let the spaced form through. ([#58](https://github.com/ANFAIA/QUMO/pull/58); its regression test was tightened in [#59](https://github.com/ANFAIA/QUMO/pull/59), 2026-11-25)
- Hardware plugin: `status` and `result` no longer build the provider from whatever `provider_options` a job file holds. A file in `~/.qumo/hardware/jobs` with `"provider_options": {"url": "https://other.example/api", "username": "x"}` made the SpeQtrum client log in at that host with the API key of the environment. Only `client` and the options a provider declares in `JOB_OPTIONS` (IBM `channel`, `instance`, `account_name`, `use_fractional_gates`; Quantinuum `project`; local `use_fractional_gates`) are read back; an endpoint or credential name is refused with QM-E959 before any request, and the endpoint and credentials come from the current environment as at submit. Job file names now escape unsafe characters as `%XX`, so `a/b` and `a_b` are two files (they shared `a_b.json`); a file stored under the old name is still found. (project review, 2026-11-25)

Before, only the last component was checked: with a file `secrets/a.txt`, `read_file("secrets/a.txt")` and `read_file("ok/../secrets/a.txt")` returned its text, `search_code` returned its lines and `list_files` listed it together with `.env` and `x.pem`. Now `read_file`, `list_files`, `search_code`, the sandbox `write_file` / `edit_file` and the file arguments of `run_check build/qumo` refuse such a path, and listings and searches hide those files and symlinks that lead to them or out of the root (`agents/mojo/qumo_agent/tools/repo.mojo`; the golden fixture is regenerated from the Python tools). (project review, 2026-11-25)
- Credential redaction in error texts. Hardware plugin: `safe_exc_text` left `x-api-key: <key>`, `Invalid credentials key <key>`, `Authorization: Basic ...`, `password=...` and `secret=...` readable for a 32-character key and turned `access_token=<key>` into `access_<redacted>`; the CLI printed `QM-E999: unexpected <Type>: <text>` (and the `QUMO_HW_DEBUG=1` traceback) with no redaction. Lower-case hexadecimal digests of 40 or 64 digits and UUID job ids are no longer replaced (a SHA-256 was). Mojo agent harness (`util/redact.mojo`): `bearer` and `basic` in any letter case, the whole header value (dots and base64 signs included), the JSON-escaped form of each known value, and every variable of the process whose name looks secret, not only three names. Both follow one length rule for known values: 8 characters or more anywhere, 4 to 7 only as a whole word, under 4 never (`docs/HARDWARE_PLUGINS.md`, `agents/mojo/DESIGN.md` 2.2.4). ### Changed

- **Moved import paths**: the agent-tool handlers of `exec` and `ft` are in `qumo/ai`, so `ai` is the top package and nothing below imports it (pure moves: tool names, schemas, error codes and outputs are the same). `qumo.exec.tools` is now `qumo.ai.exec_tools` (`register_exec_tools`, `precision_of_method`) and `qumo.ft.tools` is now `qumo.ai.ft_tools` (`register_ft_tools`, `ft_codes_json`, `gadget_checks_json`, `resource_report_json`, `default_code_names`). The old paths are removed, not re-exported: a re-export inside `exec` or `ft` would import `ai` and bring the package cycle back. The package import graph of `qumo/` has no cycle now (`ai`, `algorithms`, `exec` and `ft` were one strongly connected group); `exec` no longer imports `algorithms`. The description of the `QM-E9xx` range (`describe errors`, `docs/ERRORS.md`) names `qumo.ai, cli` in place of `qumo.ai, qumo.exec.tools, cli`. Layering in `docs/ARCHITECTURE.md`.
- Types moved to the module their role belongs to, so the low layers stop importing the high ones (pure moves: no behaviour change, no renamed public name). `Rng` is in `qumo.core.rng` (was `qumo.sim.rng`); `Target`, `parse_target`, `parse_basis`, `parse_angle_bound` and `basis_presets` are in the new `qumo.device.target`, with `basis_str` and `fmt_num` in `qumo.device.format` (were `qumo.compiler.target` and `qumo.compiler.common`); `NoiseModel`, `apply_noise_model` and the rest of the characterization and readout-mitigation code are in the new `qumo.noise.characterization` and `qumo.noise.mthree` (were `qumo.qec.characterization` and `qumo.qec.mthree`); circuit and program JSON (`circuit_to_json`, `circuit_from_json`, `write_circuit_json`, `write_param_json`, `program_to_json`, `program_from_json`, `write_program_json`) is in `qumo.ir.json` (was `qumo.ai.describe`). **The old paths are kept for one release** as modules that re-export the same names, so no existing import breaks; new code should import the new paths. `docs/ARCHITECTURE.md` has the package layering (and now lists `ft`, `gpu` and `net`). ([#60](https://github.com/ANFAIA/QUMO/pull/60), 2026-11-25)
- **Behaviour change**: `evolve`, `expectation`, `GpuStateVector.evolve` (so `evolve_gpu`/`expectation_gpu`) and `run_estimator` with `precision <= 0` (the shot path samples these instructions) now raise `QM-E416` for a circuit with a `reset`, a noise channel or a mid-circuit measurement. They used to drop those instructions silently and return the noiseless value (`x; reset` gave `<Z> = -1`, true `+1`; `expectation(x_error(1.0))` gave `+1`, true `-1`). Terminal measurements, barriers and annotations are still ignored. To drop the noise on purpose, use the new `Circuit.without_noise()` (Python: `qumo.expectation(..., noise="ignore")` does it); otherwise use `sample` or the density-matrix simulator (`check_pure_state_circuit` in `qumo/sim/runner.mojo`; `docs/SIMULATION.md`, `docs/ERRORS.md`). ([#48](https://github.com/ANFAIA/QUMO/pull/48), 2026-11-25)

### Added

- Agent check commands: `build/qumo` takes an allow-list of subcommands and options, every file argument follows the `read_file` path rules, and `-o` / `--output` needs an open sandbox and a path inside it (a read-only agent could overwrite any file of the checkout with `convert -o`, and read the first line of `.env` with `validate .env`). The native Mojo `run_check` now has the Python rules it lacked (absolute paths refused, git options as an allow-list). The Claude Code back end lists `build/qumo` subcommands one by one instead of `build/qumo:*`, so `convert` and `transpile` are no longer allowed there. `"claude_code": {"env": "scrub"}` and `"codex": {"env": "scrub"}` remove credential-looking variables of other services from the CLI's environment (opt-in, `docs/AGENTS.md` section 7). ([#54](https://github.com/ANFAIA/QUMO/pull/54), 2026-11-25)
- Agents: the rule that an agent which fetches web pages must not run code is now checked through delegation (`registry.check_web_exec`, at import; `autoresearch` and `orchestrator` reach both). Each such delegation is declared in `untrusted_subagents`, and the openrouter and local back ends return those answers, and reports copied into sandboxes or read from `agents/reports/`, inside a size-bounded `UNTRUSTED-DATA` block (`qumo_agents/untrusted.py`). `docs/AGENTS.md` states what `run_check` does not confine. The Claude Code, Codex and Mojo back ends do not wrap. ([#50](https://github.com/ANFAIA/QUMO/pull/50), 2026-11-25)
- `qumo.ft.faults`: `fault_tolerant_state_preparation`, the exact t-fault-tolerance check of post-selected state preparations (Definition 1 of Schmid and Wille, [arXiv:2611.25107](https://arxiv.org/abs/2611.25107)), with `FaultModel.circuit_level()` and `FaultModel.xz_only()`, `reduced_weight`, `count_undetected` and `single_faults`; error code QM-E738. `steane_prep_zero_ft` passes at t = 1 and the encoder alone does not. `examples/ft/ft_state_prep_check.mojo` and its Stim-only reference `examples/ft/ft_state_prep_check_stim.py` agree on every count ([FT](docs/FT.md)). (weekly job, 2026-11-23)

### Fixed

- `MatchingGraph`, `graphlike_dem` and the correlated decoder indexed `comp_dets[c][0]` for every `^` piece, so a DEM piece with no detector (`error(0.1) D0 ^ L0`, legal Stim) aborted the process with an out-of-bounds assert, and a piece with more than two detectors lost the extra ones. One helper, `graph_pieces` (`qumo/qec/decoders.mojo`), now decides: an observable-only piece is folded into the adjacent piece (its observable mask XORed in), a mechanism with no detector is skipped as undetectable, and a piece with more than two detectors is decomposed against the existing edges like an undecomposed hyperedge (dropped and counted if it cannot be). Tests in `tests/test_stim_interop.mojo`. ([#43](https://github.com/ANFAIA/QUMO/pull/43), 2026-11-25)
- MCP and CLI tool calls refuse an argument name their input schema does not declare, with QM-E801 that names it and lists the allowed names, before the tool runs. Before, a misspelt key (`shot` for `shots`) was silently ignored and the default was used, which gave a wrong answer without an error. Found by an audit of every shipped tool: `qumo_statevector`, `qumo_expectation`, `qumo_estimate_resources`, `qumo_emulate`, `qumo_density`, `qumo_to_pbc` and `qumo_ft_encode` read a `program` argument that their schemas did not list; the schemas now declare it.
- Pauli-frame sampler: a `CORRELATED_ERROR(0)` drew its geometric skip from `log1p(-0) = -0`, so the quotient was +-inf and `Int()` of it is platform-defined (a negative position would have written outside the batch). p = 0 now never draws, and the op still resets the chain, so a following `ELSE_CORRELATED_ERROR` is unchanged. Same-class check of the other channels: they were already guarded (`if p > 0`); the detector error model already ignores p <= 0. Found by reading after the Stim fix for `broadcast_pauli_errors` (Stim PR #1131); on macOS ARM64 the old sampler gave the right counts, so this is a latent undefined-behaviour fix, not a visible wrong result.

### Fixed

- Stim text import (`from_stim`, `parse_dem`, the MCP `qumo_stim_import` tool) no longer crashes or exhausts memory on untrusted input: `REPEAT` blocks nest at most 256 levels (QM-E734 / QM-E735 beyond), the detector error model parser now has the instruction budget the circuit parser has (2,000,000 lines, QM-E735; `repeat 1000000000 { error(0.1) D0 }` appended a mechanism per pass until memory ran out), and empty `REPEAT` bodies are charged per pass. At 3000 nested `REPEAT` lines the circuit parser overflowed the stack (exit 139). Same bug class as Qiskit GHSA-9g9r-qpqr-c8fr. (SDK sweep, 2026-11-23)

### Changed

- Compiler passes are declared once, in `pass_decl` (`qumo/compiler/pass_manager.mojo`): name, aliases, description and arguments with type, default, values and help. Name and alias lookup, `pass_description`, the argument check of `parse_pipeline`, its hints and the values a pass reads (`PassArgs`) come from that table, in place of six switch tables kept in step by hand; `program_compile.mojo` asks the table which passes rename qubits. Every pass name, alias and argument spelling is unchanged, and the 24 compiled test cases have the same gate counts. What differs: `key = value` with spaces is accepted by every pass (it was by `route` and the synthesis passes only); when an argument is written twice the last one counts (`cancel(1,2)` used the first, `pauli_simp(objective=t,objective=2q)` used `t`); a bad `wrap_angles` bound is reported when the pipeline is parsed, not when the pass runs; the texts of QM-E602 hints are generated and list every argument (the `route` description had lost nine); parsing a pipeline takes about 2 microseconds more and a compilation 3 to 12 microseconds more, whatever the circuit size. ### Security

- OpenQASM source is capped in what it can expand to (gate calls, unrolled loops, broadcasts, `pow`): a few bytes of source could previously ask for any amount of memory, including through the MCP server. ([#1](https://github.com/ANFAIA/QUMO/pull/1), 2026-11-03)
- MCP server: one message is at most 1 MiB (a longer line is dropped and answered with a parse error), and a call is refused with QM-E913 above `shots` = 1,000,000 or `max_qubits` = 30. The CLI and the Mojo and Python APIs keep the tools' own ranges. (security pass, 2026-11-13; not yet merged, as the next entry)
- Agent layer: the research tools fetch only public `https` addresses on the default port, the API tools only `export.arxiv.org`, `pypi.org` and `api.github.com`, every redirect is checked again and loses the `Authorization` header. `run_check` passes no variable whose name looks like a credential, takes no absolute path, and limits `git diff` / `git status` to `--stat`, `--name-only`, `--name-status`, `--cached`, `--staged`. The `autoresearch` agent no longer has the web tools; it asks `research-watch`. Commands still run without an operating-system sandbox.
